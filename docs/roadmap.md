# Roadmap

This is the order the rewrite is following and the state of each part.
The milestones are things you can run and check, not counts of functions.

## How the executable is organised

The best map of `BF2142.exe` comes from three sources recovered from the
binary itself:

- **The console API** (`symbols/*.console.csv`, 2,449 methods in the EXE and
  388 in the renderer). Every subsystem that scripts configure registers its
  methods under an object name: `ObjectTemplate` (1,403), `HudBuilder`,
  `GameLogic`, `AnimationSystem`, `collisionManager` and so on.
- **The class registry** (`docs/classes.md`, 183 classes in the EXE). Every
  manager and singleton is a `dice.hfe.*` class created through the class
  manager.
- **The start-up and level-load order**: `0x00406420` and `0x0040d270` (game
  start-up) and `0x004d3450` (level loading). `src/Main` follows them.

Template classes and their properties are in
`symbols/BF2142.exe.templates.csv` (68 types with class IDs) and
`symbols/BF2142.exe.template_properties.csv` (each property's class or
component and its field offsets).

## Verifying the rewrite

- Unit tests (`tests/`), several of which run against the installed game's
  data (`BF2142_GAME_DIR`): all meshes and textures parse, the archive
  scripts mount the right archives, sounds play.
- `bf2142 +level <name>` runs a level's scripts and reports script errors
  and unimplemented methods. All 112 installed levels currently load without
  errors beyond those the retail game also hits.
- `bf2142 --screenshot` renders a frame without a display, for checking the
  renderer.
- Drop-in DLLs (`*/retail/`) run inside the retail game under CrossOver
  (`tools/retail-swap.sh`), for modules that can be swapped one at a time.
